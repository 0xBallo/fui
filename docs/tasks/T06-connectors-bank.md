# T06 — Revolut and Widiba external connectors

Branch `feat/connectors-bank`. Owned paths: `cmd/fui-connector-revolut/`, `cmd/fui-connector-widiba/`,
`tools/anonymize/`. Read `AGENTS.md` first, then the merged `pkg/fuiproto` (records, encoder, validator,
`conformance`). Connectors import only `pkg/fuiproto` (never `internal/`).
Spec refs: functional spec "Import, export e riconciliazione" (Connettore Revolut, Connettore Widiba with all
column/causale tables), "Formato FUI" (commands, exit codes, records); technical spec "Connettori Revolut e Widiba",
"Suite di conformità", "Dati di test".

## Deliverables

1. Two executables speaking fui/1: `describe` prints the describe JSON; `fetch` reads the request JSON from stdin
   (`protocol`, `config`, `file`, `since`) and writes the record stream to stdout (`meta` with source file name +
   sha256, `account`s, `transaction`s, `balance`, `error` per unconvertible row, `end` with counts). Exit codes:
   0 ok, 2 invalid config, 3 unreadable/unrecognized source. Messages for the user only on stderr.
2. **Revolut** (CSV, UTF-8, comma, dot decimal, ISO datetimes): exact mapping of the spec table — account ref
   `revolut-<product>-<currency>` (lowercase product), Started Date → `operation_date`, Completed Date → `date`,
   payee rules for Transfer/Card Payment, amount ×100 rounded to integer **without floats** (parse the decimal text),
   Fee ≠ 0 → separate `fee` movement with an id derived from the main one, State mapping (REVERTED/DECLINED
   omitted), Balance → `balance_after` and last balance → `balance` record, Type → kind mapping, id = sha256 of the
   listed fields. Rows ordered by Completed Date.
3. **Widiba** (XLSX via `github.com/xuri/excelize/v2`, sheet "Movimenti conto"): summary block → `account` record
   `widiba-<last 4 IBAN digits>` with `iban`, final balance → `balance` record, check opening + sum = closing
   (mismatch → `error` record, not a crash); movements table from the header row containing "DATA CONT." to the
   "Totale" row, **columns located by header text, never by position**; Excel serial dates → YYYY-MM-DD; amounts
   already signed ×100 without floats; causale → kind table; payee after "A Favore" / "Ord:"; counterparty IBAN
   extraction; id from operation code in description (Bon. Ist., Bon. Sepa, Addebito Sdd N.) else sha256 of
   date, causale, description, amount and index among identical rows; "Trasferimento A/Da Linea Libera" also emits
   the opposite movement on account `widiba-linea-libera` with the same `transfer` value.
4. **Test data**: no real exports are available — build **synthetic** fixtures that follow the documented layouts
   (Revolut CSV; Widiba XLSX generated by a Go test helper with excelize, including a summary block of variable
   height). Golden `.jsonl` outputs under each connector's `testdata/` with an `-update` flag. Cover every kind /
   causale / state row in the spec tables, fees, pending, reverted, Linea Libera, identical rows.
5. Run `pkg/fuiproto/conformance` against both binaries in `go test` (build them in the test).
6. `tools/anonymize`: a small Go program that consistently replaces names, IBANs and descriptions in a Revolut CSV
   or Widiba XLSX (same input → same replacement within a file), so real exports can be added later safely.
